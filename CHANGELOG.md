# Changelog

SERAPH uses semantic versioning while it remains a formalized prototype.

## [0.1.0] - 2026-10-14

Status: public research alpha source; not published to PyPI or npm.

### Added

- Deterministic Python governance kernel for invariant closure checks.
- HTTP sidecar entrypoint for runtime governance.
- Adapter examples for agent runtimes, CI/CD gates, tool guards, delegation,
  OpenClaw, coupling field telemetry, and CHANDRA/AMLA session monitoring.
- Scenario corpus and regression tests for traceable governance behavior.
- Lean 4 formalization of constraint-frame closure, commit soundness, and
  witness preservation.
- Lean 4 formalization of consequence reachability, exact affected-set and
  downstream-effect coverage, topology observation, and omission blocking.
- Manifold Constraint Closure with scoped, three-state, non-scalar relations.
- OpenClaw operational trajectory mapping with missing symbolic-pressure
  observations preserved as unknown, separate from tool-name changes.
- Reproducible runtime-governance validation corpus with seventeen bounded
  admission, adversarial, execution-binding, consequence, and audit cases.
- Versioned consequence edges, deterministic transitive affected-set closure,
  and explicit downstream-inhabitant effect coverage.
- Installable CLI examples and scenario corpus validated from the built wheel.
- Static proof-surface demo whose checked-in evidence is generated by the real
  compiler and consequence monitor.
- Machine-readable validation evidence retained by CI with explicit OWASP and
  certification claim boundaries.
- OpenClaw host-event validation for parallel calls, retries, missing and
  duplicate hooks, ambiguous fallback correlation, and early after-hook races.
- Deferred early execution evidence is released only after governance proposal
  registration; outcome rejection or sidecar unavailability is surfaced.

### Fixed

- Malformed sidecar response shapes now return an explicit deny rather than
  throwing after governance response parsing; HTTP fault-injection checks run in CI.
- Docker includes the installable validation harness. The cloud SDK used by
  the CHANDRA live example is now an optional `chandra` extra.

- OpenClaw tool-name switching and diversity no longer fabricate symbolic
  pressure, topic coherence, or recursion observations. Missing pressure stays
  null; explicit pressure evidence and required-evidence checks remain enforced.
- The OpenClaw adapter reads plugin-scoped settings and recognizes the native
  `read` tool. Mixed read/exec workflows reach the independent environment gate.

### Notes

- This is a research artifact and formalized prototype, not a certified
  production safety system.
- Public package publication is intentionally deferred until release readiness
  has been reviewed explicitly.
- The former fixed authority-vector API and its attributed specification were
  removed from the active architecture before release.
